## 알려진 제한 (blocker 결함과 구분 — 아래는 known limit)

- **실제 느린 소켓의 7s 중단은 미측정**: native property 왕복(`BLOCKING_SEND_TIMEOUT` = Long 7000)·binder 부팅·unit fake raw close 실측까지이며, 실 Tomcat + slow client 통합 실측은 없다.
- **SSE 느린 클라이언트 backpressure·실부하 튜닝 미측정**: `synchronized(connection)` 안의 `SseEmitter.send`가 느린 구독자에서 블로킹되면 단일 스레드 broadcaster가 지연될 수 있다(구현 의도 범위, blocker 아님).
- **SSE 403 원인 미확정**: 재현 시도(10 round·30 opens)로 미재현.
- WS 주기 heartbeat 없음 · message 포화는 drop(연결 자동 close 없음)이나 **15s 주기 resync가 자동 `SNAPSHOT`으로 재연결 없이 복구**하며(`SeatAutoResyncTest`: 1s 설정으로 검증, 기본 15s), 명시 재조회·재연결은 추가 선택지 · **TCP 절단 후 자동 재구독은 검증 완료**(killed=4), subscription executor의 **거부(포화) 후 recovery·실부하 튜닝은 별도 미측정**.
